## Data model (schema `app`; every table RLS; no direct writes from the API unless stated)
- **Who acts**: every write RPC records `private.acting_operator_id()`. In `identity` it equals
  `private.current_operator_id()`; `tablet-kiosk` extends it (device account → cashier chosen by PIN).
  Modules must call `acting_operator_id()`, never `auth.uid()` directly, for the movement operator.
- `app.settings` (singleton row, `id boolean primary key default true check (id)`):
  `cents_per_point int > 0 default 100`, `confirm_threshold_cents int > 0 default 15000`,
  `usb_uid_format text default 'hex'` (values defined by card-input), `updated_at`, `updated_by → operators`.
  Read: active operators. Write: admins only, via RPC `app.update_settings(...)`.
- `app.customers`: `id uuid`, `name text` (trimmed, 1–80, unique case- and accent-insensitive),
  `email text null` (optional, lower-case, unique: SPEC-customers-v2 point 2; the customer's phone is no
  longer collected), `privacy_consent_at timestamptz not null`, `notes text null`, `created_at`,
  `created_by → operators`, `anonymized_at timestamptz null`, `last_activity_at timestamptz null`
  (SPEC-customers-v2 point 6).
- `app.cards`: `id uuid`, `uid text` (uppercase hex, no separators, `^[0-9A-F]{8,20}$`),
  `customer_id → customers`, `active boolean`, `associated_at`, `associated_by → operators`,
  `deactivated_at null`, `released_at null` (SPEC-customers-v2 point 4). At most one active card per
  customer (partial unique index). A uid is reused for another customer only after an admin reformats
  the card (`release_card`; `cards_uid_key` is unique among the rows not released).
- `app.rewards`: `id uuid`, `name text unique ci`, `points int > 0`, `active boolean default true`,
  `created_at`. Read: active operators. Write: admins (RPC or policies).
- `app.movements`: `id uuid`, `operation_id uuid unique not null` (generated by the app, idempotency),
  `customer_id`, `kind 'purchase'|'redemption'|'correction'`, `amount_cents int null` (purchase only,
  > 0), `points int not null` (signed: purchase +, redemption −, correction = −points of the corrected
  one), `cents_per_point int null` (rate in force, purchase only), `reward_id uuid null`,
  `description text null` (reward name snapshot or free-reward description), `operator_id not null`,
  `created_at timestamptz default now()`, `corrects_movement_id uuid null unique` (a correction points
  to the movement it cancels; "annullato da" is derived from it). Never updated or deleted.
- **Balance** = `sum(points)` over all movements of the customer (corrections included). Never < 0:
  checked in the same transaction as the write, with the customer row locked (`for update`).
- Write RPCs (security definer, `set search_path = ''`, role checks inside, idempotent on
  `operation_id`: a repeated call returns the first result instead of failing):
  `app.record_purchase(p_operation_id, p_customer_id, p_amount_cents)`,
  `app.redeem_reward(p_operation_id, p_customer_id, p_reward_id)`,
  `app.redeem_free_reward(p_operation_id, p_customer_id, p_description, p_points)`,
  `app.cancel_movement(p_operation_id, p_movement_id)` (operator: only own purchase/redemption within
  10 s of `created_at`; admin: any purchase/redemption; a purchase cannot be cancelled if the balance
  would go below zero; a movement is cancelled at most once).
  Each returns the movement row plus the new balance.

## Operators (module operators, added 2026-11-22, [SPEC-operators.md](SPEC-operators.md))
Built after the other modules; no existing table, RPC or route is renamed.
- **Route**: `/impostazioni/operatori` (admins; an operator sees the `AdminsOnly` view), reached from the
  first row of GESTIONE in `/impostazioni` ("Operatori"). Phone and tablet layouts (480 px "Invita
  operatore" column). `/imposta-password` gains the invite version (`type=invite`).
- **New columns of `app.operators`** (still read-only from the API, profiles never deleted):
  `deactivated_at timestamptz null` (null = active), `deactivated_by → operators`, `invited_at timestamptz
  null` (last invite sent from the app), `invited_by → operators`. The email stays in `auth.users`.
  A deactivated profile is not an operator: `private.current_operator_id()`, `private.valid_cashier_id()`,
  `app.get_session_identity()`, `app.list_cashiers()` and `app.unlock_cashier()` ignore it, so its token
  reads 0 rows and every write is refused; `private.add_operator()` reactivates the profile it relinks.
- **RPCs for the app** (`authenticated`, `is_admin()` inside, `42501` otherwise):
  `app.list_operators()` → `id, name, role, status ('active'|'invited'|'deactivated'|'removed'), email,
  has_pin, is_me`; `app.set_operator_role(p_operator_id, p_role)`; `app.set_operator_active(p_operator_id,
  p_active)`; `app.operator_invite_begin`, `app.operator_resend_begin`, `app.operator_cancel_begin` (called
  only by the Edge Function with the caller's token). The other steps (`app.operator_invite_finish`,
  `_fail`, `_orphan`, `app.operator_resend_finish`, `app.operator_cancel_check`) are executable by
  `service_role` only. Reservations in `private.operator_invites` (no API privilege).
- **Edge Function** `supabase/functions/operator-invites` (the project's first, `verify_jwt = true`):
  `POST` with `action` `invite` (`operation_id`, `name`, `email`, `role`, idempotent on `operation_id`),
  `resend` or `cancel` (`operator_id`). Only Origins in `APP_ORIGINS` (+ `APP_PREVIEW_ORIGIN` on staging);
  `redirectTo` = `<Origin>/imposta-password`. The secret key exists only in the Edge runtime: never in the
  app, Vercel, logs or the repo. The app calls it only from `supabaseOperatorsService.ts`
  (`functions.invoke('operator-invites')`).
- **Error codes** of the module: `EO001` last active admin, `EO002` oneself, `EO003` profile without an
  account, `EO004` not waiting for an invite, `EO005` an admin from a device (invite, promotion or
  reactivation) without the cashier's PIN; plus the standard `42501`, `22023`, `P0002`. With the PIN (till
  tablet only, decided 2026-11-23): `app.set_operator_role_with_pin(p_operator_id, p_role, p_pin)`,
  `app.set_operator_active_with_pin(p_operator_id, p_active, p_pin)` (jsonb `{status: 'ok', operator}` |
  `wrong_pin {attempts_left}` | `locked {lock_seconds_left}`, the counter and lock of `unlock_cashier`) and
  the fifth argument `p_pin` of `app.operator_invite_begin` (the function body's `pin`; 403 `wrong_pin` /
  `pin_locked`).

## Card input (module card-input)
One app-wide reader service with adapters: Web NFC (Chrome Android), USB keyboard-wedge (tablet),
and a fake adapter for tests. In E2E the production build is made with `VITE_E2E=1` (set by
`playwright.config.ts`), which exposes `window.__enjoyFakeCard(uid)` ONLY in that build; normal builds
must tree-shake it away. Every uid goes through one `normalizeUid()` to uppercase hex.

## Process rules (from CLAUDE.md, restated because they bite)
Code/commits/comments English; UI and docs Italian. Amounts always integer cents. Tests first (TDD).
Touch targets ≥ 48 px. No real personal data anywhere. No secrets in the repo. Components get data only
through feature services/hooks. Oxlint `--deny-warnings`, Prettier, `exactOptionalPropertyTypes`.
